> [!info] Quick Summary
> 
> As your database grows, you need tools to manage complex logic, automate tasks, ensure data safety, and optimize query speeds. This page covers Subqueries, Indexes, Views, Transactions, Stored Procedures, and Triggers.

## 1. Subqueries (Nested Queries)

A subquery is a query nested inside another query (like `SELECT`, `INSERT`, `UPDATE`, or `DELETE`). It helps break down complex logic into smaller, manageable parts.

```sql
-- Find all users who earn MORE than the company's average salary
SELECT * FROM users 
WHERE salary > (
    SELECT AVG(salary) FROM users
);

-- Find users who were referred by high earners
SELECT name FROM users 
WHERE referred_by_id IN (
    SELECT id FROM users WHERE salary > 75000
);
```

## 2. Database Optimization: Indexes

Indexes work like a book's index. They drastically speed up data retrieval operations (`SELECT`, `WHERE`) on specific columns.

> [!warning] The Cost of Indexes
> 
> Do not index every column! While indexes speed up _reading_ data, they consume extra disk space and slow down _writing_ data (`INSERT`, `UPDATE`, `DELETE`) because the index must be updated every time the data changes.

```sql
-- View existing indexes on a table (Primary Keys are indexed automatically)
SHOW INDEXES FROM users;

-- Create a single-column index (e.g., if you frequently search by email)
CREATE INDEX idx_email ON users(email);

-- Create a multi-column index (order matters!)
CREATE INDEX idx_gender_salary ON users(gender, salary);

-- Remove an index
DROP INDEX idx_email ON users;
```

## 3. Virtual Tables: Views

A View is a "virtual table" based on the result set of a saved `SELECT` query. It does not store data itself; it provides a live snapshot of the underlying tables. Useful for simplifying complex joins so you don't have to rewrite them.

```sql
-- Create a view for high-earning users
CREATE VIEW rich_users AS 
SELECT id, name, email FROM users WHERE salary > 70000;

-- Query the view exactly like a normal table
SELECT * FROM rich_users;

-- Delete a view
DROP VIEW rich_users;
```

## 4. Transactions & Data Safety (TCL)

By default, MySQL runs in "Auto-Commit" mode (every query is saved instantly). For dangerous operations, you can turn this off to test your queries safely using `COMMIT` (save) and `ROLLBACK` (undo).

```sql
-- Step 1: Turn off auto-commit (0 = off, 1 = on)
SET autocommit = 0;

-- Step 2: Run a potentially dangerous query
DELETE FROM users WHERE id = 5;

-- Step 3a: If you made a mistake, undo it to the last commit state
ROLLBACK;

-- Step 3b: If everything looks correct, make the changes permanent
COMMIT;

-- Step 4: Turn auto-commit back on for normal use
SET autocommit = 1;
```

## 5. Automation: Stored Procedures & Triggers

### Stored Procedures

A saved block of SQL code that can be executed later. Great for encapsulating complex logic or multiple queries. You must temporarily change the `DELIMITER` so MySQL doesn't stop reading at the first semicolon.

```sql
-- Change delimiter so the whole block compiles together
DELIMITER $$ 

CREATE PROCEDURE add_user(IN p_name VARCHAR(100), IN p_email VARCHAR(100))
BEGIN
    INSERT INTO users (name, email) VALUES (p_name, p_email);
    SELECT * FROM users WHERE email = p_email; -- Return the new user
END $$

-- Change delimiter back to standard semicolon
DELIMITER ; 

-- Execute the stored procedure
CALL add_user('John Doe', 'john@example.com');
```

### Triggers

A special stored program that executes _automatically_ just before or after an `INSERT`, `UPDATE`, or `DELETE` event. Useful for maintaining audit logs or automatically updating related columns.

```sql
DELIMITER $$

-- Create a trigger that logs every time a new user is inserted
CREATE TRIGGER after_user_insert 
AFTER INSERT ON users 
FOR EACH ROW 
BEGIN
    -- 'NEW' refers to the newly inserted data row
    INSERT INTO user_logs (user_id, action) 
    VALUES (NEW.id, 'New user created');
END $$

DELIMITER ;
```
