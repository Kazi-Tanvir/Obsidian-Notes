# 3.3 The Product — Compact Note

---

## Manager's Dilemma

- Plan needed **now** → but solid info **unavailable**, requirements are **fluid**
- Solution: Establish and **bound the scope** early
- Unbounded characteristic → **major project risk**

---

## 3.3.1 Software Scope

> **First project management activity** = determine software scope

### Three Scoping Questions

| Question | Asks about |
|----------|------------|
| **Context** | How software fits in larger system; constraints from context |
| **Information Objectives** | Input & output data objects |
| **Function & Performance** | Data transformation; special performance needs |

### Statement of Scope must include:

- **Quantitative data** (e.g., max users, response time)
- **Constraints** (e.g., cost limits memory)
- **Mitigating factors** (e.g., algorithms available in C++)
- Must be **unambiguous + bounded + understandable** at management & technical levels

---

## 3.3.2 Problem Decomposition

- Also called: **partitioning** / **problem elaboration**
- Strategy: **Divide and conquer** → complex → smaller manageable parts
- Two areas: **(1) Functionality** to deliver · **(2) Process** to deliver it
- During scoping → **no full decomposition** — just enough for estimation
- Each feature = **subfunction** → can be further refined
