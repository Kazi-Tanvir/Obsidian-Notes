# 3.4 The Process — Compact Note

---

## Core Idea

- 3 generic phases: **Definition · Development · Support**
- Choose the right **process model** → define **preliminary plan** → do **process decomposition**
- Avoid **process overkill**

## 3.4.1 Melding Product & Process

- Product + Process decomposition happen **simultaneously**

### CPF — 6 Framework Activities (always the same)

| Activity | Key Word |
|----------|----------|
| Customer Communication | Requirements elicitation |
| Planning | Resources, timelines |
| Risk Analysis | Technical & management risks |
| Engineering | Build representations |
| Construction & Release | Build, test, install, support |
| Customer Evaluation | Feedback on representations |

- **Product–Process Matrix:** Functions (rows) × Framework Activities (columns) → work tasks in cells
- Framework activities = **invariant**; work tasks = **vary per project**

---

## 3.4.2 Process Decomposition

### Quick Model Selection Guide

| Situation | Model |
|-----------|-------|
| Small, similar to past | Linear Sequential |
| Tight time + compartmentalized | RAD |
| Can't deliver full functionality on time | Incremental |
| Uncertain requirements / breakthrough tech | Evolutionary models |

### Key Rule

- **CPF is invariant** — fits all paradigms (linear, iterative, evolutionary, concurrent, component-based)
- **Work tasks vary** — more complex project → more tasks for the same framework activity
- Process decomposition = asking **"How do we accomplish this CPF activity?"**
