# Day 46 - JavaScript Garbage Collection Internals, Generational Hypothesis & V8 Heap Snapshots

## SECTION 1: IN-DEPTH THEORY & SYNTAX

### 1. The Weak Generational Hypothesis & V8 Heap Partitioning

The foundational assumption behind V8's memory architecture is the
**Weak Generational Hypothesis**: *most objects die shortly after
creation* (typically over \$90%\$ of allocated variables, loop counters,
temporary closures, and intermediate strings).

To optimize CPU cycles, V8 divides its memory heap into distinct
generational spaces with specialized garbage collection algorithms:

### 2. Major GC: Tri-Color Concurrent Marking & Write Barriers

Major GC (Full Garbage Collection) processes the Old Space. Pausing
JavaScript execution for a full heap scan causes unacceptable UI freeze
frames and API timeouts.

V8 uses **Concurrent Tri-Color Marking**:

- **White**: Unvisited objects; candidate for garbage collection.

- **Grey**: Object discovered by GC; queued for scanning, but its
  referenced children have not yet been evaluated.

- **Black**: Object discovered and all its outgoing pointers visited;
  guaranteed to survive.

#### The Concurrency Mutation Problem & The Write Barrier:

While background GC threads mark objects, the main JavaScript thread
continues running and mutating object properties. If the main thread
takes an already-marked **Black** object and attaches a new **White**
object to it:

blackObject.newProperty = whiteObject;

A naive GC would never revisit blackObject, accidentally sweeping
whiteObject and causing catastrophic memory corruption! To prevent this,
V8 injects a **Write Barrier** into compiled machine code. Whenever a
reference is written, the write barrier checks if a Black object is
pointing to a White object, immediately coloring the child **Grey** to
ensure it is scanned.

### 3. Interpreting Chrome DevTools Heap Snapshots

When diagnosing memory leaks, developers inspect DevTools Heap Snapshots
using two key metrics:

- **Shallow Size**: The physical byte size of the object header and its
  direct internal properties (e.g. an empty object has a shallow size of
  \~28--32 bytes).

- **Retained Size**: The total memory freed if this specific object was
  deleted (the object\'s shallow size plus the size of all transitive
  child objects reachable *exclusively* through it).

#### The Subtle Lexical Closure Context Trap:

A notorious memory leak occurs when closures share the same parent
lexical environment:

// The Shared Lexical Environment Memory Leak

let runLeak;

function setup() {

const hugePayload = new Array(1000000).fill(\'leak\'); // \~8 MB memory

// Closure 1: Uses hugePayload

function leakHolder() {

return hugePayload\[0\];

}

// Closure 2: Does NOT use hugePayload, but shares lexical scope with
Closure 1!

runLeak = function activeListener() {

console.log(\"Active worker running\...\");

};

}

setup();

// Even though \`leakHolder\` is never saved or called, \`runLeak\`
keeps the

// shared parent lexical scope alive, permanently leaking
\`hugePayload\`!

### V8 Engine Diagnostic & GC Flags:

  -----------------------------------------------------------------------
  **Node.js CLI Flag**                **Primary Diagnostic Purpose**
  ----------------------------------- -----------------------------------
  \--trace-gc                         Prints one-line summaries of every
                                      Minor and Major GC event with
                                      timing.

  \--trace-gc-verbose                 Prints byte-level breakdown of all
                                      heap spaces before/after GC.

  \--expose-gc                        Exposes global gc() function for
                                      programmatic testing.

  \--max-old-space-size=4096          Sets maximum Old Space ceiling
                                      (e.g. 4096 MB = 4 GB).

  \--inspect                          Opens Chrome DevTools protocol port
                                      for live Heap Snapshots.
  -----------------------------------------------------------------------

### Memory Leak Diagnostic Heuristics:

1.  **Detached DOM Nodes**: Elements removed from DOM via removeChild()
    but still held by a JavaScript event listener or variable reference
    (Detached HTMLDivElement in DevTools).

2.  **Global Event Listeners / Intervals**: Forgotten
    window.addEventListener() or setInterval() holding references to
    unmounted components.

3.  **Unbounded Cache Maps**: Growing Map or Array without LRU limits or
    WeakRef wrapping.
