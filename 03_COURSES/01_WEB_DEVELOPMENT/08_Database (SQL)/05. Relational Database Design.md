> [!info] Quick Summary
> 
> Relational databases shine because they allow you to link separate tables together and enforce strict rules on your data. This page covers Constraints, Primary Keys, and Foreign Keys.

## 1. Data Constraints

Constraints are rules applied to columns to prevent invalid data from being inserted into the database. This ensures data accuracy and reliability.

- `UNIQUE`: Ensures all values in a column are different (e.g., no two users can have the same email).
- `NOT NULL`: Ensures that a column cannot be left empty.
- `DEFAULT`: Automatically assigns a fallback value if the user doesn't provide one.
- `CHECK`: Verifies that the data meets a specific condition before allowing the insert/update.


```sql
-- Adding constraints during table creation
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    sku_code VARCHAR(50) UNIQUE,
    price INT CHECK (price > 0),
    in_stock BOOLEAN DEFAULT TRUE
);

-- Adding a constraint to an existing table
ALTER TABLE users 
ADD CONSTRAINT check_dob CHECK (date_of_birth > '1900-01-01');
```

## 2. Primary Keys

A **Primary Key** uniquely identifies each record in a table. It is essentially a combination of the `NOT NULL` and `UNIQUE` constraints.

> [!abstract] Primary Key Rules
> 
> - A table can only have **one** Primary Key.
>     
> - It cannot contain `NULL` values.
>     
> - In MySQL, it is typically paired with `AUTO_INCREMENT` so the database handles generating unique IDs automatically (1, 2, 3...).
>     

```sql
-- Standard Primary Key implementation
CREATE TABLE employees (
    emp_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100)
);

-- Resetting the AUTO_INCREMENT starting value (e.g., start IDs at 1000)
ALTER TABLE employees AUTO_INCREMENT = 1000;
```

## 3. Foreign Keys & Relationships

A **Foreign Key** is a column (or set of columns) in one table that refers to the Primary Key in another table. This creates a "link" or relationship between the two tables, preventing orphaned data.

### Creating a Relationship

Imagine separating user details and user addresses into two tables to keep the database organized.

```sql
-- 1. Parent Table
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100)
);

-- 2. Child Table with a Foreign Key
CREATE TABLE addresses (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT, 
    city VARCHAR(100),
    CONSTRAINT fk_user 
        FOREIGN KEY (user_id) REFERENCES users(id) 
        ON DELETE CASCADE
);
```

### Deletion Actions (`ON DELETE`)

When you link tables, you must tell the database what to do if the "Parent" record (the User) is deleted.

- `ON DELETE CASCADE`: If the parent row is deleted, automatically delete all related child rows (e.g., if a User is deleted, delete their Address too).
- `ON DELETE SET NULL`: If the parent is deleted, set the child's foreign key column to `NULL` (keeps the address, but unlinks it).
- `ON DELETE RESTRICT`: Prevents the parent from being deleted if any child rows still reference it.
