> [!info] Quick Summary
> 
> Joins are used to combine rows from two or more tables based on a related column (like a Foreign Key). This allows you to reconstruct separated data into a single, comprehensive view.

## 1. Standard Joins

Assume we have two tables: `users` (Left Table) and `addresses` (Right Table), linked by `addresses.user_id = users.id`.

### `INNER JOIN`

Returns only the records that have matching values in **both** tables. If a user has no address, they will not appear in the results.

```sql
SELECT users.name, addresses.city 
FROM users
INNER JOIN addresses ON users.id = addresses.user_id;
```

### `LEFT JOIN`

Returns **all** records from the Left table (`users`), and the matched records from the Right table (`addresses`). If there is no match, the right side will contain `NULL`.

```sql
SELECT users.name, addresses.city 
FROM users
LEFT JOIN addresses ON users.id = addresses.user_id;
```

### `RIGHT JOIN`

Returns **all** records from the Right table (`addresses`), and the matched records from the Left table (`users`). If there is no match, the left side will contain `NULL`.

```sql
SELECT users.name, addresses.city 
FROM users
RIGHT JOIN addresses ON users.id = addresses.user_id;
```

## 2. Combining Result Sets (`UNION`)

While `JOIN` combines columns horizontally, `UNION` stacks result sets vertically. Useful when you have tables with identical schemas (e.g., `users` and `admin_users`) and want a single consolidated list.

> [!abstract] UNION Rules
> 
> - Both `SELECT` statements must have the same number of columns.
>     
> - The columns must have similar data types.
>     
> - The columns must be in the same order.
>     

### `UNION` (Removes Duplicates)

Combines the data but automatically filters out duplicate rows.

```sql
SELECT name, email FROM users
UNION
SELECT name, email FROM admin_users;
```

### `UNION ALL` (Keeps Duplicates)

Combines the data and keeps every single record, even if it is a duplicate. It is also slightly faster than standard `UNION` because it skips the deduplication process.

```sql
SELECT name, email FROM users
UNION ALL
SELECT name, email FROM admin_users;
```

## 3. Self Joins

A Self Join is a regular join, but the table is joined with _itself_. This is extremely useful for hierarchical data or referral systems (e.g., finding out which user referred another user).

> [!tip] Aliases are Mandatory
> 
> To join a table to itself, you must use aliases (like `A` and `B`) to trick SQL into treating it as two completely separate tables.

```sql
-- "A" represents the referred user, "B" represents the referrer
SELECT 
    A.name AS user_name, 
    B.name AS referred_by_name
FROM users A
LEFT JOIN users B ON A.referred_by_id = B.id;
```
